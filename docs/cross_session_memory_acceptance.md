# 跨会话记忆验收

本轮改动把回答后的记忆处理结果写入 `chat_messages.memory_status`，并通过 SSE 完成事件及历史消息接口返回。状态含义：

- `saved`：本轮至少一次插入或更新调用成功返回；不代表已做跨会话召回验证。
- `unchanged`：识别到候选记忆，但已有内容无需更新。
- `skipped`：未识别出长期记忆，或生成被停止。
- `failed`：记忆判断、冲突处理或写入阶段报错；回答仍可完成，可能已有部分记忆写入。
- `unknown`：旧消息或旧版调用没有可确认的结果。

后端使用迁移 `migrations/20261027_chat_memory_status.sql` 为已有数据库增加列；本地 `agent_learning` 已应用。其他环境需要在部署新版 API 前运行该迁移，`create_all` 不会修改已有表。

## 由用户进行的真实验收

1. 用账号 A 在会话 1 发送“我叫张三”。完成后查看该轮助手消息在 `chat_messages.memory_status` 的值；预期 `saved` 或 `unchanged`，如为 `failed`，前端应显示记忆写入失败提示。
2. 新建会话 2，发送“我叫什么？”；预期回答能说出张三，服务端召回日志出现 `user_name`。会话 ID 应与会话 1 不同，账号 ID 相同。
3. 在会话 2 发送“我改名叫李四了”，再新建会话 3 问“我叫什么？”；预期回答为李四，且同一账号的 `user_name` 不应同时保留冲突的旧值。
4. 刷新页面，确认会话 3 仍在历史列表，记忆失败提示（若有）仍能在消息上看到。
5. 用账号 B 问“我叫什么？”；不应读出账号 A 的姓名。

这些步骤需要真实模型和 Milvus，离线测试不能证明回答内容和实际召回质量。
