# RAG 问题与改进清单

审查日期：2026-11-09。

本清单记录当前代码静态审查发现的能力边界和改进项，不代表已通过真实文档、模型和数据库的效果评测。下文状态保留初审时记录；当前进度见 [todo.md](todo.md)，实测与限制见 [verification.md](verification.md)。优先级表示建议顺序，不表示问题已经在所有请求中复现。

当前已有：知识库与个人记忆分离、有效文档版本校验、相似度阈值、来源记录、显式 `/knowledge` 检索模式。以下改进应保留这些行为。

## 1. 缺少实际评测结果

- **优先级：高；状态：待处理。**
- **位置：**[评估记录模板](../../docs/knowledge_rag_eval.md)、[检索配置](../../src/agent/knowledge_store.py)。
- **现状：**评估记录仍为空模板；初始 COSINE 阈值 0.40、Top 5、800 字符分块尚无固定问题集的效果数据支撑。
- **影响：**难以区分漏检、误检和生成错误，也无法证明调整参数后有改善。
- **改进方向：**固定文档版本与问题集，覆盖明确事实、同义改写、跨片段、无答案、冲突以及替换/删除后的旧事实。
- **验证标准：**记录基线 Hit@5、无答案误引用、来源准确率和答案依据；调整参数后使用同一批样本比较，不预设未经验证的达标数字。

## 2. 只有向量检索，缺少关键词召回与重排

- **优先级：高；状态：待处理。**
- **位置：**[search_knowledge_chunks](../../src/agent/knowledge_store.py)。
- **现状：**问题直接编码，以 COSINE 分数筛选并返回片段；没有关键词检索、重排或文档多样性控制。
- **影响：**错误码、产品型号、精确条款等问题可能漏检；多个相似片段可能挤占前五名。
- **改进方向：**评估关键词与向量混合召回、候选重排、重复片段去重以及同一文档的结果数量控制。
- **验证标准：**对精确标识、语义改写、重复片段样本比较命中率、误命中和耗时，保留有效的最小方案。

## 3. 分块未保留足够的文档结构

- **优先级：高；状态：待处理。**
- **位置：**[prepare_document](../../src/agent/knowledge_ingest.py)。
- **现状：**固定 800 字符、120 字符重叠；PDF 逐页切分，没有按标题、条款或表格进行专门处理，也没有检索后扩展相邻片段。
- **影响：**标题与正文、跨页条款、表格说明可能分离；答案可能漏掉条件、例外或限定范围。
- **改进方向：**保存章节路径与块序号，按文档类型切分；按需要补充相邻片段，并设置上下文长度预算。
- **验证标准：**使用跨页条件、标题依赖、长条款、表格与注释样本检查证据完整性及最终回答。

## 4. 引用缺少生成后的校验

- **优先级：高；状态：待处理。**
- **位置：**[_knowledge_evidence](../../src/agent/chat_workflow.py)、[research_result](../../src/agent/research_agent.py)。
- **现状：**提示词要求关键事实标注来源，但没有在生成后检查编号有效性，也没有校验事实是否得到引用片段支持。
- **影响：**可能出现来源真实、引用编号存在，但结论超出原文的回答。
- **改进方向：**先校验引用编号属于本轮结果，再评估关键结论与引用证据的对应关系；缺乏依据的结论应重新生成或明确无法确认。
- **验证标准：**覆盖不存在的引用编号、引用无关片段、部分有依据、文档冲突和无答案场景；来源列表与答案支持程度分别评估。

## 5. 普通聊天检索路由与研究摘要可能丢失证据

- **优先级：中；状态：待处理。**
- **位置：**[build_agent](../../src/agent/main.py)、[研究 Agent](../../src/agent/research_agent.py)、[显式知识库模式](../../src/agent/chat_workflow.py)。
- **现状：**普通聊天由主 Agent 决定是否调用 research，再由研究 Agent 选择工具；显式 `/knowledge` 模式才会直接检索。研究结果交给主 Agent 的来源摘录最多保留前 300 字。
- **影响：**库中有答案也可能没有查询；关键证据位于片段后半段时，主 Agent 更依赖研究摘要。显式模式会向提示词提供完整命中片段，不应与此摘要路径混为一谈。
- **改进方向：**明确必须查询知识库的触发场景，评测普通聊天的工具选择；按问题选择证据摘录或允许按 chunk ID 获取完整片段。
- **验证标准：**比较普通模式和显式模式的检索触发情况；测试答案位于第 300 字以后的片段，确认主 Agent 仍能获得直接证据。

## 6. 文档重建与索引故障恢复能力不足

- **优先级：中；状态：待处理。**
- **位置：**[文档管理接口](../../api/routers/knowledge.py)、[index_document](../../src/agent/knowledge_store.py)。
- **现状：**原始文件不归档；上传请求内同步完成解析和索引，没有持久化后台任务及断点恢复。向量清理失败时记录日志，没有自动补偿任务。
- **影响：**更换 Embedding 或分块策略后需要重新上传；大文档请求等待较久，异常后可能留下孤立或废弃向量。
- **改进方向：**按需求归档原始文件及解析配置，记录 Embedding 版本；引入可查询状态、重试和幂等的索引任务，以及孤立向量对账清理。
- **验证标准：**模拟解析、向量化、批量写入、元数据提交与清理失败，检查状态可解释、重试不产生重复有效数据且旧版本不会被错误暴露。

## 7. 有效版本后过滤存在扩展成本

- **优先级：中；状态：待处理。**
- **位置：**[_active_revisions 与 search_knowledge_chunks](../../src/agent/knowledge_store.py)。
- **现状：**先查 Milvus，再用 PostgreSQL 过滤无效版本；候选不足时扩大窗口，最多 1000 条。每次有效版本核验新建 PostgreSQL 连接。
- **影响：**废弃版本积累可能挤占候选，窗口上限外的有效结果无法返回；扩大搜索窗口与重复建立连接会增加延迟。
- **改进方向：**优先补充废弃向量清理、数据库连接池和检索耗时记录，再根据规模评估检索前过滤或索引组织方式；保留 PostgreSQL 的有效版本校验。
- **验证标准：**构造大量旧版本和少量有效版本，记录命中率、候选数量、数据库连接量和延迟分布，验证删除及替换的正确性不退化。

## 8. 文件解析和共享管理权限仍较基础

- **优先级：解析为中；正式多人环境的权限要求需先明确；状态：待处理。**
- **位置：**[文件解析](../../src/agent/knowledge_ingest.py)、[文档管理接口](../../api/routers/knowledge.py)。
- **现状：**PDF 无 OCR；表格与复杂版式没有专门解析。当前有意采用共享知识库，所有登录用户可上传、替换和删除文档，没有进一步区分管理角色。
- **影响：**扫描件无法入库，复杂版式可能损失语义；任何登录成员对共享文档的修改都会影响其他用户后续检索。
- **改进方向：**按实际文件类型评估 OCR 和表格解析；明确共享编辑政策，若需要受控管理，则增加角色、操作授权及审计记录。当前共享行为本身不应直接认定为跨用户泄漏漏洞。
- **验证标准：**以扫描件、双栏 PDF、表格和带脚注文档验证提取结果；按明确后的权限矩阵测试上传、替换、删除和审计。

## 建议实施顺序

1. 建立固定问题集和基线结果。
2. 根据漏检与误检样本优化分块、召回、去重和重排。
3. 校验答案引用及证据支持程度。
4. 优化普通聊天检索路由与研究结果传递。
5. 完善原始文件归档、后台索引、失败恢复和废弃向量清理。
6. 按实际文档类型、数据规模和多人使用要求完善解析、性能和权限。
