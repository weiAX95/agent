## 实际答案与路由审核（Codex，非用户人工终验）

用户授权使用现有模型做少量固定题。模型使用现有默认 profile（usage 报告的模型名为 `tongyi-xiaomi-analysis-pro`），主 Agent checkpoint 仅在内存中，关闭用户记忆提取与写入；使用合成问题，不读取真实用户会话。Codex 逐份核对原始文档和实际工具来源，模型自审仅为辅助；这不是用户本人或第三方人工终验。

首轮发现：普通模式曾把“工作日开放”推断为“春节不开放”，且先出现的网页 URL 挤占了来源预算。已补充内部证据优先和普通研究链路的可选支持性核验，再复测同类问题。

## 真正的进程故障与租约验证

在独立 schema/database 内启动子进程，真实写入 Milvus，并使用 `os._exit(23)` 终止：

- 向量写入后崩溃：文档没有发布；租约过期后重试成功。
- SQL flush 后、事务提交前崩溃：数据库回滚，没有半份有效文档；重试成功。
- 两种恢复后，单片段的向量数量均为 1，重复执行完成任务不再创建向量。
- 旧 worker 写完向量后暂停，强制过期租约，由新 worker 完成；旧 worker 恢复时得到 lease_lost，不能覆盖发布结果。

最新复测结果：`output/rag/rag_eval_a85f3e796ddc4242/faults.json`；旧版本记录也保留。不是仅用抛异常替代进程终止。

```sh
.venv/bin/python -m tools.rag_sandbox --faults-only
```

## 1000 条废弃向量与清理

向临时 Milvus 数据库注入 1000 条高分过期修订，令其排在有效片段之前：

- 检索扩大到 1000 条窗口后明确报告不完整，没有伪装成正确的无答案结果。
- 显式全向量盘点并清理后，重新返回有效文档。
- 清理始终跳过当前有效 revision 和运行中的任务。

原始结果：`output/rag/rag_eval_e36e1acfc66f4e27/scale.json`，含清理前后窗口、候选数量、过期过滤与元数据耗时。此为边界测试，不代表百万文档负载测试。

```sh
.venv/bin/python -m tools.rag_sandbox --profile vector_v2 --scale
```
