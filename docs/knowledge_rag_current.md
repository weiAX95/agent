# 共享知识库 RAG：当前实现

2026-11-10 更新。实现与操作：[RAG 配置及迁移](rag/operations.md)；问题与进度：[待办](rag/todo.md)；真实结果：[首轮实测](rag/verification.md)；评测工具：[使用说明](rag/evaluation.md)。

知识库与个人记忆分开：`agent_memory` 保存个人事实，`agent_knowledge_v1` 保存共享文档片段；旧 `demo_collection` 不迁移、不删除。共享知识库默认由所有登录用户管理，可显式配置管理员名单模式。

## 数据流

1. 上传 TXT、Markdown、DOCX、PDF。校验文件边界后按 revision UUID 归档原文件，再提交持久索引任务。默认同步等待任务完成；`background=true` 返回 202，由独立 worker 处理。
2. PostgreSQL 的 `knowledge_index_jobs` 记录原文件哈希、解析/模型配置、状态、租约与次数；worker 解析、分块、Embedding，将确定性 chunk ID 的向量 upsert 到 Milvus。
3. 向量准备完成后，在一个 SQL 事务内发布有效文档 revision、`knowledge_chunk_records` 分块及关键词目录、任务完成状态与操作审计。并发替换和删除会阻止过期任务发布。
4. 检索始终核对 `knowledge_documents` 中的有效版本。默认向量检索，可切换 SQL 关键词与向量融合，并可扩展同一有效 revision 的相邻片段。
5. `/knowledge` 以及明确的知识库/文档意图先直接检索；其他问题由主 Agent 决定是否调用 research。研究子 Agent 仅接收本次 query，不共享主 Agent 的 checkpoint。
6. research 返回 `status/summary/sources`，有内部文档时附完整 `evidence`，避免来源卡片前 300 字截断关键条件。最多 5 个来源，内部证据优先；正文单片段上限为 4096 UTF-8 字节。网页只有 URL 时不冒充内部原文。
7. 知识库模式缓冲正文，验证本轮 [K序号] 后才输出。可选的事实支持核验使用当前模型并单独计费；开启时普通内部研究答案也在核验后输出。失败会更正同一 AIMessage ID 的 checkpoint，再输出保守说明。正文仍为普通 Markdown。
8. SSE 与历史事件保存短来源，主 Agent 的 ToolMessage/checkpoint 保存实际工具结果。来源列表不是“每句话都已得到支持”的保证；语义核验也需人工抽查。

## 文件和解析边界

文件最多 10 MB，正文最多 20 万字符、300 块，PDF 最多 100 页。默认结构化分块 v2：基础 800 字符、120 重叠，附不超过 200 字符的标题路径；表格分段重复表头，过长单行明确要求拆分。分块 v1 仍可配置，旧文档不自动重建。

DOCX 保留标题与表格；PDF 可选布局提取。本地 OCR 默认关闭：扫描件无文本时仍提示先 OCR；开启需本机 Tesseract 和语言包，最多 20 页、单页 2000 万像素和 30 秒。没有自动安装依赖，也未验证本机实际扫描识别效果。

## 管理接口

文档列表、上传、替换、删除路径保持不变，均要求登录。默认共享编辑保留；admin 模式下只有名单内用户可修改。列表/成功上传的元数据增加 revision 和 sha256。

新增任务查询、重试、从归档重新索引与审计接口；路径及状态契约见 [operations.md](rag/operations.md)。客户端使用相同 request_id 安全重试同一请求，不复用到其他文件或操作。

任务采用 PostgreSQL 租约与发布前 fencing，最多执行三次，进程崩溃可恢复。只有 completed publication 才参与检索，后台任务尚未执行不会伪报完成。独立 worker 及清理命令需显式运行。

## 已验证与仍需注意的部分

- 真实隔离服务上的固定 24 题：原始分块/向量 Hit@5 为 80%，结构化分块/向量为 95%；混合策略在 v2 上没有额外收益，默认仍向量，相邻扩展默认关闭。
- 默认 0.40 阈值的 4 道无答案题仍都误召回；提高阈值会损失有答案命中。可选支持核验和保守回答不能当作检索误召回已经解决。
- 已完成 6 份真实答案的 Codex 原文审核、真实进程退出/回滚/租约接管以及 1000 条废弃向量清理恢复。小样本结果不外推真实业务质量或大规模性能。
- 检索连接使用有界 SQL 连接池；关键词使用 GIN 索引。窗口耗尽且没有有效结果会报告不完整，而非正确的无答案空结果。
- 原文件默认保存在 output/knowledge，需持久化卷和备份。历史旧文档没有原文件时仍需重新上传；新版本配置需要从归档重新索引。
- 删除阻止后续检索，但不自动擦除归档和过去聊天。保留周期由部署者管理。
- 新表与策略未部署到正式服务，此次数据库建表和故障测试仅发生于临时隔离资源；最终清理记录在本地 output/rag/。
- 所有真实记录与完整操作边界见 [实测记录](rag/verification.md)。
