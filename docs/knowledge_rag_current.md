# 共享知识库 RAG：当前实现

状态：代码已接入；真实 PostgreSQL、Milvus、模型和浏览器结果尚未由用户验收。这里的知识库与 [个人长期记忆](memory_current.md) 分开：`agent_memory` 保存用户事实，`agent_knowledge_v1` 保存所有登录用户共享的文档片段。旧 `demo_collection` 仍是独立演示集合，本功能不会删除或迁移它。

## 数据流

1. 登录用户在前端知识库面板上传 TXT、Markdown、DOCX 或 PDF。后端在 [入库模块](../src/agent/knowledge_ingest.py)中校验文件、提取文字并切块，使用现有 BGE Embedding 生成向量。
2. [文档接口](../api/routers/knowledge.py)把文档的名称、大小、内容类型、上传者、分块数和当前版本记入 PostgreSQL `knowledge_documents`；[向量存储](../src/agent/knowledge_store.py)把文字片段及文档 ID、版本、页码放入 Milvus `agent_knowledge_v1`。原始上传文件不保留；替换时需要重新上传文件。
3. 聊天主 Agent 需要资料时调用 `research` 子 Agent。子 Agent 可选用 [知识库检索工具](../src/agent/web_tools.py)；检索以 COSINE 分数取候选，过滤低相关片段，并核对 PostgreSQL 中仍有效的文档版本。普通聊天不强制检索。
4. 工具命中的文档 ID、片段 ID、名称、页码和摘录进入研究事件的 `sources`。SSE 和历史消息都保存该事件；前端在执行时间线及回答旁显示来源。网页来源继续使用 URL 字符串，旧历史事件仍可读取。

聊天输入区的“查知识库”开关会在本轮消息前加入 `/knowledge` 命令。后端识别命令后，在主 Agent 回答前直接检索共享知识库，并将最多五个片段及 `[K1]` 至 `[K5]` 编号放入本轮提示词和持久化研究事件。回答中出现的编号可在来源列表中找到对应片段。命令是消息正文的一部分，因此重试时仍使用同一模式；普通聊天继续由 Agent 判断是否需要 research。无命中或检索服务不可用时，提示词要求明确说明无法依据知识库核实。

检索资料可能包含错误内容或试图改变 Agent 行为的文字。提示词把它作为证据而非指令；来源由工具结果生成，不采用模型自行编造的链接。来源列表表示本轮检索过的资料，不保证答案的每一句都得到该资料支持。

## 管理接口

所有接口都要求 Bearer 登录凭证；所有登录用户都可查看、上传、替换和删除共享文档。
替换或删除会影响所有用户随后进行的检索，因此前端删除操作需要明确确认。

| 方法与路径 | 用途 | 输入或结果 |
| --- | --- | --- |
| `GET /api/knowledge/documents` | 列表，按创建时间倒序分页 | `limit`（1–100）、`before_created_at` 与 `before_id`；返回 `items`、`next_before` |
| `POST /api/knowledge/documents` | 上传并索引 | `multipart/form-data`，字段名 `file`；成功返回文档元数据 |
| `PUT /api/knowledge/documents/{id}` | 以新文件替换当前版本 | 同上；旧版本只在新版本完成索引和元数据切换后停用 |
| `DELETE /api/knowledge/documents/{id}` | 移除文档 | 先软删除元数据，再清理向量；已删除版本不参与检索 |

上传上限为 10 MB；最多提取 20 万字符、300 个片段，PDF 最多 100 页。TXT/Markdown 要使用 UTF-8。PDF 使用文字提取，没有 OCR；纯扫描件无可检索文字时返回明确错误。检索初始 COSINE 阈值为 `0.40`，可通过 `KNOWLEDGE_MIN_SCORE` 设置 0 到 1 之间的值；该默认值只是待评估的起点，不代表已校准的准确率。

## 当前边界

- 文件解析和索引在上传请求内完成，大文档会使请求等待；尚无后台任务与进度恢复。
- 尚未做关键词与向量混合检索、重排或经过固定问题集校准的阈值；效果记录模板见 [RAG 评估记录](knowledge_rag_eval.md)。
- 删除或替换后如 Milvus 清理暂时失败，旧片段可能暂留在向量库，但有效版本核对会阻止它们进入回答。检索会扩大候选范围寻找有效片段；大量废弃向量持续堆积仍可能造成漏检，后续需要运维清理机制。
- 删除文档阻止后续检索，但过去的聊天回答与研究事件可能已保存该文档的短摘录；当前删除接口不回写历史聊天。
- 文档正文只保存在 Milvus 片段中，原始文件没有归档或下载接口。若需要重新建立索引，需重新上传来源文件。
- 网页抓取只允许公开 HTTP/HTTPS 地址，禁用跳转并限制响应为 1 MB、正文为 2 万字符。DNS 校验到实际连接之间仍可能发生地址变化；对外部署时仍需网络出口规则阻断内网访问。
- 真实上传、跨用户共享、重启恢复、删除后不可检索和答案来源准确性尚待用户安排验收；当前文档不宣称这些场景已通过。
