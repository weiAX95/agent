# Agent 执行过程持久化

目标：用户生成时可看检索进度；刷新或切换会话后，仍能看到同一轮实际发生的执行过程。只记录可核验的阶段、状态与来源，不记录模型内部思维链。

## 实施步骤

- [x] 1. 定义事件契约和 PostgreSQL 表：按 assistant message 归属，保存顺序、阶段、状态、摘要和来源；旧消息兼容空事件。
- [x] 2. 后端写入：阶段事件先提交数据库，再发 SSE；失败、停止、重放均反映真实状态。
- [x] 3. 历史读取：在原有会话归属校验后批量查询事件，随消息返回，避免逐条查询。
- [x] 4. 前端：实时事件和历史事件使用同一数据结构，在助手消息中可展开查看；刷新后恢复。
- [x] 5. 离线验证：后端持久化、权限和重放回归；前端解析、恢复和构建。真实模型、Milvus 和浏览器验收由用户执行。

事件展示边界：来源仅来自实际工具调用和结果；不展示工具原文、密钥、完整网页或推测出的“思考”。
