# Agent 产品进度与路线

基准日期：2026-10-23。状态来自代码与已有验证记录，不代表线上验收。本轮只制定规划，不实现功能、不部署、不推送。

## 产品方向与假设

建议方向：帮助个人持续推进学习目标的 Agent 助手。第一位用户是项目作者本人；随后邀请少量愿意反馈的体验者。选择这个方向，是因为已有 LearningPath、Topic、Task 与相关 API，可复用现有资产。此定位是规划假设，不代表已做用户调研。

产品承诺：把一个目标变成用户认可、能够执行、下次可以继续的计划。

核心路径：提出目标 → 补充关键约束 → 生成计划草稿 → 用户修改确认 → 保存路径与任务 → 执行与记录 → 下次继续 → 周期复盘。

首版场景：“我想用四周补齐 Agent 开发能力，每周投入十小时，请结合当前进度安排任务。”Agent 应询问缺失信息、生成可编辑草稿，经确认保存，并能回答“今天应该继续哪项”。不承诺替用户自动完成学习本身。

## 版本路线

时间为单人每周约 15～20 小时的初始排期假设，总体约 6～8 周；不是交付承诺。首轮真实联调后重新估算。每个阶段通过退出条件后再推进。

### V0.1 可持续聊天（约第 1～2 周）

用户价值：今天说过的话，明天打开还能继续，出错后知道如何处理。

范围：真实模型/数据库聊天验收；双用户隔离；会话列表、打开历史和刷新恢复；新事实存取验证；错误提示与重试。

退出条件：
- 从登录到聊天、停止、失败重试、同会话重启恢复、记忆跨会话召回均有实测记录。
- 两个测试用户不能读写对方的会话、任务和记忆；任何隔离失败均阻止进入试用。
- 作者连续自用三天，记录问题，不以测试通过代替真实体验。

### V0.2 目标变成计划（约第 3～4 周）

用户价值：从一句目标得到可编辑、可保存的执行计划。

范围：目标与约束澄清；结构化计划草稿；任务卡片编辑；确认后保存到现有路径/主题/任务模型。

退出条件：
- 一条目标可完成“澄清 → 草稿 → 修改 → 确认 → 保存 → 刷新后查看”。
- 未确认的草稿不写入正式任务；取消不产生正式记录；重复确认不重复创建。
- 每个任务有明确产出与完成标准；不可只生成“学习相关知识”等不可验收描述。
- 超时、字段不合法、保存失败时提示真实状态，不显示假成功。

### V0.3 推进与复盘（约第 5～6 周）

用户价值：能继续执行，并结合实际完成情况调整计划。

范围：今日任务、状态更新、学习记录、基于实际任务状态的下一步建议；新计划调整仍先预览再确认；检索资料时展示来源与工具执行状态。

退出条件：
- 用户可完成任务并重新打开查看结果；Agent 的进度描述与任务数据库一致。
- Agent 能解释推荐下一项的依据；数据不足时询问，不编造完成情况。
- 计划变更有前后对比且经确认；保存失败可以安全重试。
- 展示正在执行的动作、工具状态和结果摘要，不展示或依赖模型私有思维链。

### V0.4 小范围试用与改进（约第 7～8 周）

用户价值：基本任务稳定可用，反馈能带来可观察的改进。

范围：可重复部署、基本运行监控、使用说明；先自用一周，再邀请 3～5 位自愿体验者；建立真实评测基线与问题优先级。

退出条件：
- 同一批样本有模型、提示词、代码版本及质量/耗时/成本记录；修复前后可比较。
- 真实失败和负反馈经审核、脱敏后进入回归集。
- 记录用户是否完成核心流程及放弃原因，决定继续完善或调整方向。
- 部署可按文档重复执行，有健康检查、数据备份与恢复验证；通过后才对外提供入口。

## 质量与产品指标

下面是首轮试用的测量方案及候选门槛，不是已达成结果。先建立基线，再调整目标。

| 指标 | 定义与用途 | 首轮验收方式 |
| --- | --- | --- |
| 核心流程完成率 | 成功保存可查看计划的次数 / 启动计划流程次数；取消与失败分开记录 | 固定 20 个目标样本，候选目标 ≥18 个完成；小样本不外推线上成功率 |
| 计划可用性 | 用户是否接受或经有限修改后接受，记录改动原因 | 人工评审任务是否具体、符合时间约束、可验收 |
| 写入正确性 | 确认、取消、重试后正式记录是否符合预期 | 未确认写入、重复创建和越权读写为阻断问题，不允许遗留 |
| 记忆效果 | 应存/不应存、应召回/不应召回、更新是否正确分别计数 | 姓名、偏好、改名、引用、假设、跨用户等固定用例，单独报告错误 |
| 响应体验 | 首 token、完整回复、计划保存耗时分别测量 | 报告样本数与 p50/p95；不足以统计时列原始分布，不虚设结果 |
| 调用成本 | 每次成功计划的模型调用、token 与实际可得费用 | 供应商缺失 usage 时标记未知，不伪造精度 |
| 持续使用 | 作者能否在一周内连续推进同一目标；体验者是否回来更新任务 | 记录行为和访谈反馈，区分测试操作与真实使用 |

## 范围控制与风险

- 暂缓多 Agent、通用工具市场、复杂管理后台、广泛多模态和多行业适配。先交付一条可持续使用的任务链。
- 不把自动长期记忆当作任务数据库：任务和进度以结构化业务记录为准；长期记忆保存个人背景及偏好。
- 计划确认不等于所有事实可靠；仍需格式校验、业务校验、权限检查和结果核验。
- 真实联调可能发现依赖、配置、隔离和一致性问题，V0.1 优先修复，后续排期顺延。
- 真实模型输出有波动；测试替身只证明链路，不能证明提取与规划质量。
- 前端在 ../web/my-app，后端在当前仓库；交付时必须同时记录两个版本。
- 不回填历史聊天，不向真实用户库写入验收数据；使用隔离测试账号与数据。
